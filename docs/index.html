01　どんなライブラリか

channel-mapは、検出器の識別情報と読み出しフロントエンド（FEE）のアドレスを相互に対応付けるC++17のライブラリです。CSVから対応表を読み込み、DAQや解析コードからチャンネル情報を取得できます。

FEE：IP下位2オクテット ＋ CH ⇄ 検出器：名前・面・セグメント・番号・読み出し名

主な機能

  • チャンネルの検索と設定登録にはchmap::ChannelMapDopenessを使います。FEE側のIPアドレス下位2オクテットとチャンネル番号から、検出器の識別情報を取得します。
  • 逆方向の検索は、初期化時に有効化できます。
  • 検索キーを配列の添字に変換する「dope vector」により、整数での検索を直接アクセスに結び付けます。
  • 検出器名などの文字列はCSVから辞書を作り、内部では整数インデックスとして保持します。
  • 検出器ごとの幾何情報や較正情報を関連付けられます。

このガイドで扱うこと

  • 対応表CSVの作成とライブラリのインストール
  • FEEアドレスと検出器識別子の正引き・逆引き
  • 幾何情報・較正情報の登録と参照
  • 入力の制約、エラーの扱い、検索時の前提条件

02　インストールとプロジェクトへの組み込み

必要な環境

  • C++17対応コンパイラ
  • CMake 3.10以上
  • CMakeで使うビルドツール（MakeやNinja等）

ROOTは不要です。Gitはcloneでソースを取得するときだけ使用する任意のツールで、展開済みのソースからのビルドには不要です。バージョンは同梱のVERSIONファイルから取得します。

以下のインストール手順はLinuxを想定しています。

ビルドとインストール

git clone https://github.com/SATSUKIUM/channel-map.git
cd channel-map
cmake -S . -B .build -DCMAKE_BUILD_TYPE=Release   -DCMAKE_INSTALL_PREFIX="$HOME/.local/channel-map"
cmake --build .build --parallel
cmake --build .build --target install
  • ZIP等を展開した場合や既存のチェックアウトでは、展開先へ移動してcmakeの行から実行してください。git cloneは不要です。
  • NESTDAQ配下へ導入する場合は、インストール先に"$NESTDAQ"を指定します。
  • Release・Debugともに、ROOTなしでライブラリとサンプルプログラムをビルドします。
  • ライブラリ、ヘッダ、バージョン情報を含むCMake設定、dope-skeleton-programがインストールされます。

利用側のプロジェクトに組み込む

利用側のCMakeLists.txtに以下を追加します。

cmake_minimum_required(VERSION 3.10)
project(ChannelMapExample LANGUAGES CXX)
find_package(ChannelMap REQUIRED)
add_executable(channel-map-example main.cpp)
target_compile_features(channel-map-example PRIVATE cxx_std_17)
target_link_libraries(channel-map-example PRIVATE ChannelMap::ChannelMap)
cmake -S . -B build -DCMAKE_PREFIX_PATH="$HOME/.local/channel-map"
cmake --build build --parallel
./build/channel-map-example ./example.csv
  • ライブラリをインストールした後、利用側も同じ版のヘッダとライブラリで再ビルドしてください。
  • CMAKE_PREFIX_PATHには、channel-mapのインストール先を指定します。
  • 利用側のリンク先にはChannelMap::ChannelMapを指定します。

03　対応表CSVを用意する

9列のヘッダとデータ例

対応表には以下の9列をこの順序で用意します。

fe.id,fe.channel,fe.data,detector.id,detector.plane,detector.segment,detector.channel,detector.readout,detector.data
0xc0a802a9,8,0,utof,0,0,0,left,0
0xc0a802a9,10,0,utof,0,0,0,right,0
列内容・制約
fe.id整数で記したIP。例は192.168.2.169。検索では下位16bit（2, 169）のみを使います。
fe.channelFEEチャンネル番号。uint8_t、0〜255。
fe.data予約列。対応付けでは未使用。
detector.id検出器名。文字列として辞書に登録（例：utof）。
detector.plane面名。文字列として辞書に登録（例：0）。
detector.segmentセグメント番号。uint8_t、0〜255。
detector.channel検出器チャンネル番号。uint16_t、0〜65535。
detector.readout読み出し名。例：left、right。辞書で整数化。
detector.data予約列。対応付けでは未使用。

CSVの記述ルール

  • ヘッダは省略せず、余分な空白を入れないでください。
  • 予約列も0などで埋め、空セルを避けてください。
  • 単純なカンマ分割です。引用符によるカンマのエスケープ、空白の除去、コメント行は実装していません。
  • 空行は読み飛ばします。

数値の表記と予約値

  • fe.idは基数自動判定で整数に変換します。
  • 他の数値列は数字だけかを先に判定するため、通常の10進表記（不要な先頭ゼロなし）を推奨します。
全ゼロのFEEアドレスは予約値です。
  • (ip3rd, ip4th, ch) = (0, 0, 0)は未登録スロットを表します。
  • この組み合わせを含むCSVは、読み込み時にstd::runtime_errorで拒否されます。
  • CH0など、個々のフィールドが0であることは問題ありません。

付属の対応表

リポジトリに含まれるmapdata_T103_20260404.csvを、9列形式の対応表の例として参照できます。実際の処理には、使用する装置の接続に合った対応表を用意してください。

04　基本の使い方：正引きと逆引き

初期化と検索の前提

上のCSVをexample.csvとして保存し、次のコードをmain.cppに置きます。検索には、存在確認と取得をまとめたfindDET()／findFE()を使います。

  • 処理開始時に一度だけ初期化します。
  • initialize()の第2引数にtrueを指定すると、逆引き用配列も作成します。既定値はfalseです。
  • isInitialized()とhasInverseMap()による準備完了の確認は、InitTask()などで一度だけ行ってください。
RUN中の検索では初期化状態を確認しません。
  • 初期化前の検索は、APIの前提条件違反です。
  • 逆引き配列を作成せずにfindFE()を呼ぶことも、前提条件違反です。

正引き・逆引きのコード例

#include <chmap/channel_map_dopeness.hpp>
#include <iostream>
#include <memory>
#include <utility>

int main(int argc, char* argv[]) {
    if (argc != 2) {
        std::cerr << "Usage: " << argv[0] << " map.csv\n";
        return 1;
    }
    auto& map = chmap::ChannelMapDopeness::get_instance();
    const double fill_ratio = map.initialize(argv[1], true);
    std::cout << std::dec << "FE fill ratio: " << fill_ratio << '\n';

    // FE -> DET：登録がなければnullptr（配列範囲内の穴も含む）
    const auto* det = map.findDET(2, 169, 8);
    if (!det) return 2;
    std::cout << det->getDetectorName() << ' '
              << det->getDetectorPlane() << ' '
              << static_cast<unsigned>(det->segment) << ' '
              << det->channel_number << ' '
              << det->getReadoutChannelName() << '\n';

    // DET -> FE：名前、面、segment、読み出し名、番号の順
    const auto* fe = map.findFE("utof", "0", 0, "left", 0);
    if (!fe) return 3;
    std::cout << std::dec << static_cast<unsigned>(fe->ip3rd) << '.'
              << static_cast<unsigned>(fe->ip4th) << ':'
              << static_cast<unsigned>(fe->ch) << '\n';

    // Itemを渡すオーバーロードも利用できる
    if (map.findFE(*det) != fe || map.findDET(*fe) != det) return 4;
}

このCSVなら正引き結果はutof 0 0 0 left、逆引き結果は2.169:8です。

戻り値と診断出力

  • initialize()の戻り値はFE側の配列充填率で、成功／失敗を表すboolではありません。
  • 初期化時にはライブラリ自身の診断ログを出力します。
  • 重複項目や1 GBを超える配列見積もりの警告は、標準エラー出力へ出ます。
API戻り値と未登録時の動作
findDET(ip3rd, ip4th, ch) / findDET(FEAddrItem)const DETIdItem*。初期化成功後に使用。範囲外・範囲内の未登録スロットではnullptr。
findFE(名前, 面, segment, 読み出し名, 番号)const FEAddrItem*。逆引き配列の作成後に使用。未登録・未知の名前・数値範囲外ではnullptr。
findFE(名前ID, 面ID, segment, 読み出しID, 番号) / findFE(DETIdItem)const FEAddrItem*。辞書インデックスを使う逆引き。未登録時はnullptr。

取得したItemの参照

  • 返されたポインタからItemをそのまま参照でき、getterによる再取得は不要です。
  • ポインタは、マップの格納領域が再構築・破棄されるまで有効です。
  • 並行する初期化・変更はサポートしません。

キーを直接扱う場合

  • getDopeKey_*のtrueは各フィールドが範囲内という意味で、登録済みを保証しません。
  • getDETIdItem()／getFEAddrItem()は、無検査の添字アクセスです。
  • 存在確認にはfind系を使ってください。正引きと逆引きのキーは互換ではありません。

05　Itemと辞書

Itemに保持される情報

  • FEAddrItemはip3rd、ip4th、chを保持します。
  • DETIdItemはname、plane、segment、channel_number、readout_channel、および設定への内部参照を保持します。
  • 設定はgetConfiguration()から読み取り専用で参照します。
  • uint8_tはストリーム出力で文字として扱われます。数として表示するときはキャストしてください。

辞書インデックスの割り当て

CSV全体を先に走査し、名前の重複を取り除き、文字列をソートしてインデックスを割り当てます。

  • インデックスはCSVの内容に依存します。固定値として保存・ハードコードしないでください。
  • 検出器名IDの0は未登録用です。有効な名前は1〜255で、最大255種類です。
  • 面名・読み出し名は0〜255で、それぞれ最大256種類です。
  • 上限を超えると、辞書構築時にstd::runtime_errorが発生します。
  • 予約ID 0のdetname_dictionary.IndexToString()はfalseを返します。

名前とインデックスを相互に参照する

uint8_t name_index;
if (map.detname_dictionary.StringToIndex("utof", name_index)) {
    std::string original;
    map.detname_dictionary.IndexToString(name_index, original);
}
  • 公開辞書はdetname_dictionary、plane_dictionary、readout_channel_dictionaryです。
  • 通常は初期化で構築された辞書を参照し、手動の追加・再構築を避けます。
  • 逆引きには、文字列版・インデックス版・DETIdItem版のオーバーロードがあります。

06　幾何情報・較正情報を関連付ける

所有権と登録API

設定情報の所有者はマップです。DETConfItemが幾何情報・TDC較正・ドリフト長較正を所有し、利用側はDETIdItem::getConfiguration()から読み取り専用のconstポインタを借ります。

  • 対応表CSVから設定値を読み込む処理はありません。利用側で作成・登録します。
  • setGeometry()、setTdcCalibration()、setDriftCalibration()に、用途に応じたunique_ptrを渡します。
  • 成功した設定は、呼び出し側の変数がスコープを抜けても、マップの破棄まで生存します。
  • 未登録の設定を取得するとnullptrが返ります。

幾何情報・較正情報の登録例

基本例でdetの存在を確認した後、main関数内に追加するコードです。

auto geom = std::make_unique<chmap::GeomItemDC>();
geom->SetGlobalPosition(0.0, 0.0, 100.0);
geom->SetResolution(0.1, 0.1, 0.1);
geom->SetRotationAngles(0.0, 0.0, 0.0);
geom->SetWireGeometry(1.0, 5.0, 0.0);
geom->CalcWirePosition(det->channel_number);
if (!map.setGeometry(*det, std::move(geom))) return 5;

const auto* config = det->getConfiguration();
if (config && config->getGeometry()) {
    std::cout << config->getGeometry()->GetGlobalZ() << '\n';
}
auto tdc = std::make_unique<chmap::CalibrationItem_DCTdcCalib>();
tdc->SetTdcCalibration(0.0, 1.0);
if (!map.setTdcCalibration(*det, std::move(tdc))) return 6;

auto drift = std::make_unique<chmap::CalibrationItem_DCDriftLength>();
drift->SetApproximation(2, {0.0, 0.05}); // 係数の個数と配列長を合わせる
if (!map.setDriftCalibration(*det, std::move(drift))) return 7;

const auto* tdc_view = config->getTdcCalibration();
const auto* drift_view = config->getDriftCalibration();
// 型付きのconstポインタなので、較正の取得にdynamic_castは不要。
std::cout << tdc_view->GetScale() << ' '
          << drift_view->GetDriftLength(10.0) << '\n';

登録先の指定方法

登録先使い方
DETIdItemsetGeometry(*det, std::move(geom))。識別子を逆引きして実際の登録先へ対応付けるため、逆引き配列の初期化が必要です。
FEAddrItemsetGeometry(chmap::FEAddrItem{2, 169, 8}, std::move(geom))。逆引きを作成していなくても利用できます。較正の2つのAPIも同様です。

登録に失敗した場合と参照の寿命

  • 未登録チャンネル・空ポインタ・同種設定の再登録ではfalseが返ります。
  • unique_ptrは失敗時も引き取られます。失敗した呼び出しに渡した新しいオブジェクトは破棄されます。
  • 既存の登録済み設定は破棄・置換されません。借りたポインタも維持されます。
  • 借りたポインタをdeleteしないでください。
  • 登録前に保存した可変ポインタから、処理中に設定を変更しないでください。
  • DETIdItemのコピーは識別子のスナップショットです。登録先には使えますが、登録後の設定はfindDETが返す実体から読み取ってください。
  • マップの再初期化や並行変更は未対応です。

取得する設定の型

  • getGeometry()はconst GeomItem*を返します。DC固有の情報が必要な場合は、GeomItemDCへのdynamic_castを使います。
  • getTdcCalibration()とgetDriftCalibration()は、それぞれ具体的な較正型のconstポインタを返します。
  • 登録済み設定の所有権を外部へ移動したり、外部から置き換えたりはできません。

設定値の定義と現在の制約

  • CalibrationItem_DCDriftLength::SetApproximation(n, coeffs)のnは係数の個数です。少なくともn個の係数が必要です。
  • TDC較正はSetTdcCalibration(offset, scale)で設定します。
  • 幾何情報は位置・分解能がmm、角度がdegです。回転軸や回転順序には未定義の点があります。

07　運用上の注意とトラブルシューティング

配列の大きさとメモリ警告

  • FE側の配列サイズは、各要素の「最大値−最小値＋1」の積です。
  • DET側は、名前・面・segment・チャンネル番号・読み出し名の各範囲の積です。疎な対応表や逆引きでは、大きなメモリが必要になります。
  • 確保前に両配列の合計見積もりが1 GB（1,000,000,000バイト）を超える場合は、標準エラー出力へ警告します。警告だけでは確保を中止しません。
  • 見積もりには実際のItem型のsizeofを使います。CSV行・辞書・設定・アロケータ等のメモリは含みません。
  • DET側の積は64bitで計算します。32bitキーで保持できる配列サイズを超える場合は、std::overflow_errorを送出します。
  • 逆引きが不要ならfalseで初期化してください。

対応表の重複

  • 一対一を保証するのは利用者の責任です。同じキーへの代入は既存要素を上書きし、複数の対応を返すAPIではありません。
  • 初期化時にFEアドレス・DET識別子の重複を検出し、両方の対応情報と読み込み順のレコード番号を標準エラー出力へ表示します。
  • 表示する番号はCSVの物理行番号ではありません。
  • 同一内容の重複も表示します。逆引きを無効にしていてもDET重複を確認します。
  • 重複があっても初期化を続行し、自動修正・集約はしません。どの対応が採用されるかに依存しないでください。
  • 上位IPが異なっても、下位2オクテットとCHが一致すると衝突します。

数値の範囲と型変換

  • 狭い整数型への変換で、値が丸め込まれる箇所があります。
  • 文字列逆引きのint引数は、segmentの0〜255、チャンネル番号の0〜65535を検査します。
  • uint8_t等を受け取るAPIでは、呼び出す前に型変換されます。元の値が範囲内か、呼び出し側で確認してください。
  • CSV内の数値が各フィールドの範囲に収まることも、読み込む前に確認してください。

初期化と並行アクセス

  • 再初期化はサポートしていません。1プロセスにつき一度だけ初期化してください。
  • 初期化・登録と並行して検索する同期機構は用意していません。

CSV読み込み時のエラー

  • ファイルを開けない場合などは、std::exit(1)でプロセスが終了します。
  • 列数が異なる行は、エラー表示後に読み飛ばします。
  • 数値変換例外も発生し得るので、入力を事前検証してください。
  • 有効なデータ行がない場合は、std::runtime_errorで初期化を中止します。

利用側のリンクに失敗する場合

  • インストール先のlibディレクトリとCMAKE_PREFIX_PATHを確認してください。
  • インストール先を移動した場合は、利用側を新しいCMAKE_PREFIX_PATHで再設定してください。
