01　どんなライブラリか

channel-mapは、検出器の識別情報と読み出しフロントエンド（FEE）のアドレスを相互に対応付けるC++17のライブラリです。CSVから対応表を読み込み、DAQや解析コードからチャンネル情報を取得できます。

現行の中心となるクラスはchmap::ChannelMapDopenessです。FEE側のIPアドレス下位2オクテットとチャンネル番号から、検出器名・面名・セグメント・チャンネル番号・読み出し名を取得します。逆方向の検索は初期化時に有効化できます。

FEE：IP下位2オクテット ＋ CH ⇄ 検出器：名前・面・セグメント・番号・読み出し名

検索キーを配列の添字に変換する「dope vector」を使い、整数での検索を直接アクセスに結び付けます。検出器名などの文字列はCSVから辞書を作り、内部では整数インデックスとして保持します。検出器ごとの幾何情報や較正情報も関連付けられます。

この文書は上記の基準コミットを基にした日本語ドキュメントです。旧ChannelMap・ChannelMapSimple・ChannelMapDirectと関連ヘッダは廃止しました。現行APIのみを配布しています。性能値やフォーク元との差分全体を保証する文書ではありません。

02　インストールとプロジェクトへの組み込み

必要なもの：C++17対応コンパイラ、CMake 3.10以上、およびCMakeで使うビルドツール（MakeやNinja等）。ROOTは不要です。Gitはcloneでソースを取得するときだけ使用する任意のツールで、展開済みのソースからのビルドには不要です。バージョンは同梱のVERSIONファイルから取得します。

従来の開発・テスト環境はAMD Ryzen 7 3800X、AlmaLinux 9.8、GCC/G++ 11.5.0です。以下はLinuxを想定しています。

git clone https://github.com/SATSUKIUM/channel-map.git
cd channel-map
cmake -S . -B .build -DCMAKE_BUILD_TYPE=Release   -DCMAKE_INSTALL_PREFIX="$HOME/.local/channel-map"
cmake --build .build --parallel
cmake --build .build --target install

ZIP等を展開した場合や既存のチェックアウトでは、展開先へ移動してcmakeの行から実行してください。git cloneは不要です。以下のAPIを使うには基準コミット以降のコードが必要です。ライブラリをインストールした後、利用側も同じ版のヘッダとライブラリで再ビルドしてください。NESTDAQ配下へ導入する場合はインストール先に"$NESTDAQ"を指定します。ライブラリ、ヘッダ、バージョン情報を含むCMake設定、dope-skeleton-programがインストールされます。利用側との連携はCMakeに統一し、chmap-configは廃止しました。以前のインストール先に残っている同スクリプトは、今回のインストールで自動削除されません。Release・DebugともにROOTなしでライブラリと現行スケルトンをビルドします。旧APIのdebugツール、旧スケルトン、旧ヘッダ・実装は公開対象から削除しました。

利用側のCMakeLists.txt：

cmake_minimum_required(VERSION 3.10)
project(ChannelMapExample LANGUAGES CXX)

03　対応表CSVを用意する

現行APIでは以下の9列をこの順序で用意します。ヘッダは省略せず、余分な空白を入れないでください。末尾の予約列も0などで埋めます。

fe.id,fe.channel,fe.data,detector.id,detector.plane,detector.segment,detector.channel,detector.readout,detector.data
0xc0a802a9,8,0,utof,0,0,0,left,0
0xc0a802a9,10,0,utof,0,0,0,right,0
列内容・制約
fe.id整数で記したIP。例は192.168.2.169。検索では下位16bit（2, 169）のみを使います。
fe.channelFEEチャンネル番号。uint8_t、0〜255。
fe.data予約列。現行の対応付けでは未使用。
detector.id検出器名。文字列として辞書に登録（例：utof）。
detector.plane面名。文字列として辞書に登録（例：0）。
detector.segmentセグメント番号。uint8_t、0〜255。
detector.channel検出器チャンネル番号。uint16_t、0〜65535。
detector.readout読み出し名。例：left、right。辞書で整数化。
detector.data予約列。現行の対応付けでは未使用。
FEEの(ip3rd, ip4th, ch) = (0, 0, 0)は未登録スロット用の予約値です。この組み合わせを含むCSVは読み込み時にstd::runtime_errorで拒否されます。CH0など、個々のフィールドが0であることは問題ありません。

mapdata_T103_20260404.csvはこの9列形式です。古いmapdata.csvとmapdata_T103_20260311.csvはローカルのworkspace/archive/mapdata/へ退避し、公開対象から外しています。旧8列形式を移行する場合は、チャンネル番号と読み出し名を分離してください。

CSVは単純なカンマ分割です。引用符によるカンマのエスケープ、空白の除去、コメント行は実装されていません。空行は読み飛ばします。空セルは避けてください。fe.idは基数自動判定の整数変換ですが、他の数値列は数字だけかを先に判定するため、通常の10進表記（不要な先頭ゼロなし）を推奨します。旧READMEの「全要素が16進・2進等を受け付ける」という説明は現行APIに一律には適用できません。

04　基本の使い方：正引きと逆引き

上のCSVをexample.csvとして保存し、次をmain.cppに置きます。処理開始時に一度初期化してください。第2引数のtrueで逆引き用配列も作成します（既定値はfalse）。isInitialized()とhasInverseMap()による準備完了の確認はInitTask()などで一度だけ行ってください。RUN中の検索には未初期化・逆引き未作成のチェックを入れていません。初期化前の検索や、逆引き未作成時のfindFE()呼び出しはAPIの前提条件違反です。利用側のInitTask移行コミットは210efc6（nestdaq-user-implのfeat/map-owned-config）です。通常の検索には、存在確認と取得をまとめたfindDET()／findFE()を使います。

#include <chmap/channel_map_dopeness.hpp>
#include <iostream>
#include <memory>
#include <utility>

int main(int argc, char* argv[]) {
    if (argc != 2) {
        std::cerr << "Usage: " << argv[0] << " map.csv\n";
        return 1;
    }
    auto& map = chmap::ChannelMapDopeness::get_instance();
    const double fill_ratio = map.initialize(argv[1], true);
    std::cout << std::dec << "FE fill ratio: " << fill_ratio << '\n';

    // FE -> DET：登録がなければnullptr（配列範囲内の穴も含む）
    const auto* det = map.findDET(2, 169, 8);
    if (!det) return 2;
    std::cout << det->getDetectorName() << ' '
              << det->getDetectorPlane() << ' '
              << static_cast<unsigned>(det->segment) << ' '
              << det->channel_number << ' '
              << det->getReadoutChannelName() << '\n';

    // DET -> FE：名前、面、segment、読み出し名、番号の順
    const auto* fe = map.findFE("utof", "0", 0, "left", 0);
    if (!fe) return 3;
    std::cout << std::dec << static_cast<unsigned>(fe->ip3rd) << '.'
              << static_cast<unsigned>(fe->ip4th) << ':'
              << static_cast<unsigned>(fe->ch) << '\n';

    // Itemを渡すオーバーロードも利用できる
    if (map.findFE(*det) != fe || map.findDET(*fe) != det) return 4;
}

このCSVなら正引き結果はutof 0 0 0 left、逆引き結果は2.169:8です。初期化時にはライブラリ自身の診断ログも出力されます。重複項目や1 GBを超える配列見積もりの警告は標準エラー出力へ出ます。initialize()の戻り値はFE側の配列充填率で、成功／失敗を表すboolではありません。

API戻り値と未登録時の動作
findDET(ip3rd, ip4th, ch) / findDET(FEAddrItem)const DETIdItem*。初期化成功後に使用。範囲外・範囲内の未登録スロットではnullptr。
findFE(名前, 面, segment, 読み出し名, 番号)const FEAddrItem*。逆引き配列の作成後に使用。未登録・未知の名前・数値範囲外ではnullptr。
findFE(名前ID, 面ID, segment, 読み出しID, 番号) / findFE(DETIdItem)const FEAddrItem*。辞書インデックスを使う逆引き。未登録時はnullptr。

返されたポインタからItemをそのまま参照でき、getterによる再取得は不要です。ポインタはマップの格納領域が再構築・破棄されるまで有効です。並行する初期化・変更はサポートしません。

旧キーAPIの意味は変わっていません。getDopeKey_*のtrueは各フィールドが範囲内という意味で、登録済みを保証しません。getDETIdItem()／getFEAddrItem()も無検査の添字アクセスです。存在確認にはfind系を使ってください。正引きと逆引きのキーは互換ではありません。

05　Itemと辞書

FEAddrItemはip3rd、ip4th、chを保持します。DETIdItemはname、plane、segment、channel_number、readout_channel、および設定への内部参照を保持します。設定はgetConfiguration()から読み取り専用で参照します。uint8_tをストリーム出力すると文字として扱われるため、数として表示するときはキャストします。

名前の辞書はCSV全体を先に走査し、重複を取り除き、文字列をソートしてインデックスを割り当てます。インデックスはCSVの内容に依存するため、固定値として保存・ハードコードしないでください。検出器名IDの0は未登録用に予約され、有効な名前は1〜255（最大255種類）です。面名・読み出し名は0〜255（各最大256種類）です。上限を超えると辞書構築時にstd::runtime_errorが発生します。予約ID 0のdetname_dictionary.IndexToString()はfalseを返します。従来から検出器名IDが1つずれたため、保存済みのIDや固定値は再利用せず、名前から取得し直してください。

uint8_t name_index;
if (map.detname_dictionary.StringToIndex("utof", name_index)) {
    std::string original;
    map.detname_dictionary.IndexToString(name_index, original);
}

公開辞書はdetname_dictionary、plane_dictionary、readout_channel_dictionaryです。通常は初期化が構築する辞書を参照し、手動の追加・再構築を避けます。逆引きには文字列版、インデックス版、DETIdItem版のオーバーロードがあります。

06　幾何情報・較正情報を関連付ける

設定情報の所有者はマップです。DETConfItemが幾何情報・TDC較正・ドリフト長較正を所有し、利用側はDETIdItem::getConfiguration()から読み取り専用のconstポインタを借ります。未登録の設定はnullptrです。対応表CSVから設定値を読み込む処理はなく、利用側で作成・登録します。

用途別のsetGeometry()、setTdcCalibration()、setDriftCalibration()にunique_ptrを渡します。成功時はマップが保持し、呼び出し側の変数がスコープを抜けても設定はマップの破棄まで生存します。同じチャンネルへの同種設定の再登録はfalseとなり、既存の設定や借りたポインタは置き換わりません。

以下は基本例でdetの存在を確認した後、main関数内に追加するコードです。

auto geom = std::make_unique<chmap::GeomItemDC>();
geom->SetGlobalPosition(0.0, 0.0, 100.0);
geom->SetResolution(0.1, 0.1, 0.1);
geom->SetRotationAngles(0.0, 0.0, 0.0);
geom->SetWireGeometry(1.0, 5.0, 0.0);
geom->CalcWirePosition(det->channel_number);
if (!map.setGeometry(*det, std::move(geom))) return 5;

const auto* config = det->getConfiguration();
if (config && config->getGeometry()) {
    std::cout << config->getGeometry()->GetGlobalZ() << '\n';
}
auto tdc = std::make_unique<chmap::CalibrationItem_DCTdcCalib>();
tdc->SetTdcCalibration(0.0, 1.0);
if (!map.setTdcCalibration(*det, std::move(tdc))) return 6;

auto drift = std::make_unique<chmap::CalibrationItem_DCDriftLength>();
drift->SetApproximation(2, {0.0, 0.05}); // 係数の個数と配列長を合わせる
if (!map.setDriftCalibration(*det, std::move(drift))) return 7;

const auto* tdc_view = config->getTdcCalibration();
const auto* drift_view = config->getDriftCalibration();
// 型付きのconstポインタなので、較正の取得にdynamic_castは不要。
std::cout << tdc_view->GetScale() << ' '
          << drift_view->GetDriftLength(10.0) << '\n';
登録先使い方
DETIdItemsetGeometry(*det, std::move(geom))。識別子を逆引きして実際の登録先へ対応付けるため、逆引き配列の初期化が必要です。
FEAddrItemsetGeometry(chmap::FEAddrItem{2, 169, 8}, std::move(geom))。逆引きを作成していなくても利用できます。較正の2つのAPIも同様です。
unique_ptrは失敗時も引き取られ、未登録チャンネル・空ポインタ・再登録ではfalseが返ります。失敗した呼び出しに渡した新しいオブジェクトは破棄されます。既存の登録済みオブジェクトは維持されます。借りたポインタをdeleteしたり、登録前に保存した可変ポインタから処理中に変更したりしないでください。

生ポインタのregisterDETConfItem()と、公開テンプレートregisterDETConfSubItem()は廃止しました。メンバポインタや基底型を呼び出し側で指定する必要はありません。設定を外部所有する方法も廃止しています。API変更のためライブラリと利用側の両方を再ビルドしてください。

getGeometry()はconst GeomItem*を返し、DC固有の情報が必要な場合はGeomItemDCへのdynamic_castを使います。getTdcCalibration()とgetDriftCalibration()はそれぞれ具体的な較正型のconstポインタを返します。登録済み設定は外部から所有権を移動・置き換えできません。

DETIdItemのコピーは識別子のスナップショットです。コピーを登録先として渡せますが、登録後の設定はfindDETが返す実体から読み取ってください。マップの再初期化や並行変更は未対応です。

CalibrationItem_DCDriftLength::SetApproximation(n, coeffs)のnは係数の個数で、少なくともn個の係数が必要です。TDC較正はSetTdcCalibration(offset, scale)で設定します。これらの数値定義や設定値の検証は今回変更していません。幾何情報は位置・分解能がmm、角度がdegですが、回転軸や回転順序には未定義の点があります。

07　運用上の注意とトラブルシューティング

  • メモリ：FE側の配列サイズは各要素の最大値−最小値＋1の積、DET側は名前・面・segment・チャンネル番号・読み出し名の各範囲の積です。疎な対応表や逆引きでは大きなメモリが必要です。確保前に両配列の合計見積もりが1 GB（1,000,000,000バイト）を超える場合は標準エラー出力へ警告します。見積もりには実際のItem型のsizeofを使い、CSV行・辞書・設定・アロケータ等のメモリは含みません。警告だけでは確保を中止しません。DET側の積は64bitで計算し、32bitキーで保持できる配列サイズを超える場合はstd::overflow_errorを送出します。逆引きが不要ならfalseで初期化してください。
  • 重複：同じキーへの代入は既存要素を上書きします。複数の対応を返すAPIではありません。一対一を保証するのは利用者の責任です。初期化時にFEアドレス・DET識別子の重複を検出し、該当する両方の対応情報と読み込み順のレコード番号を標準エラー出力へ表示します。番号はCSVの物理行番号ではありません。同一内容の重複も表示し、逆引きを無効にしていてもDET重複を確認します。重複があっても初期化を続行し、自動修正・集約は行いません。重複時にどの対応が採用されるかに依存しないでください。上位IPが異なっても下位2オクテットとCHが一致すると衝突します。
  • 数値：狭い整数型への変換で値が丸め込まれる箇所があります。文字列逆引きのint引数はsegmentの0〜255、チャンネル番号の0〜65535を検査します。ただしuint8_t等を受け取るAPIでは呼び出す前に型変換されるため、元の値が範囲内かを呼び出し側で確認してください。CSV数値の上限検証も引き続き必要です。
  • 初期化：再初期化時にCSV行などの状態を全て消去する実装ではないため、1プロセスにつき一度の初期化を前提としてください。初期化・登録と並行して検索する同期機構は用意されていません。
  • CSVエラー：ファイルを開けない場合などはstd::exit(1)でプロセスが終了します。列数が異なる行はエラー表示後に読み飛ばされます。数値変換例外も発生し得るので、入力を事前検証してください。有効なデータ行がない場合はstd::runtime_errorで初期化を中止します。
  • リンクに失敗：インストール先のlibディレクトリとCMAKE_PREFIX_PATHを確認してください。インストール先を移動した場合は、利用側を新しいCMAKE_PREFIX_PATHで再設定してください。

移行と検証状況

新APIでは未登録判定のためにItem配列を読み、同じItemのポインタを返します。有効フラグの追加はなく、Itemの構造体サイズは変更していません。検出器名ID 0と全ゼロFEEアドレスを予約しています。

workspace/archive/tests/checked_lookup.cppは初期化状態の問い合わせ、範囲内の穴、範囲外、逆引き有無、全ゼロFEEの拒否、辞書上限、幾何情報登録を検証します。重複警告とメモリ警告はworkspace/archive/tests/initialization_diagnostics.cppで検証しています。境界値の検証には巨大配列を確保せず、診断関数を直接呼びます。逆引きの桁あふれ検出も小さなCSVで確認しています。検証コードと実行手順は公開対象には含めず、ローカルのworkspace/archive/tests/README.mdにあります。macOSの通常ビルドで検索3ケース・設定所有権2ケース・初期化診断2ケースとスケルトンの実行に成功しました。サニタイザー付き実行は起動が完了せず、合格とはしていません。
